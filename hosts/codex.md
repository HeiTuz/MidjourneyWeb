# Codex host

Use the in-app browser by default. Reuse the user's authenticated Midjourney tab through the currently supplied browser/computer tool. In the inspected desktop environment, that is `mcp__cua_repl.js` and its documented `cua` API. Read its first-call documentation before acting; a skill does not make missing tools callable.

Chrome is an explicit choice or a fallback for a confirmed obstacle. Keep the tab available through the current handoff/deliverable API when continuing work. Download and upload operations must use the documented host mechanisms.

Verified file route: default full-resolution JPG through the loaded page asset. Optional PNG uses the bundled loopback media bridge plus the current in-app pageAssets capability; see references/library.md in the installed payload. The normal website download button need not produce a usable host download event. Read capability documentation rather than inventing file methods. The bridge requires Node.js, serves only its in-memory page and should be stopped after export.

Fast path for references → Create → candidates → original JPG: inside `cua_repl`, import `scripts/codex-browser.mjs` from this installed skill directory (`let mj = await import('file://' + skillDir + '/scripts/codex-browser.mjs')`; after a reinstall, reassign `mj = await import(...)` with a new `?v=` query because modules are cached, but only after every pending navigation has settled; tracking is module-instance-local, so keep the same module and tab object until then). Each action helper below checks its own postcondition and returns a status; browser failures also come back as statuses, and only invalid arguments throw. The plain reads (`readReferences`, `listLibraryImages`, `listJobIds`, `readJobRowText`) can throw, which also means stop and inspect. Go on to the next step on `open`, `attached`, `already-attached`, `cleared`, `already-empty`, `submitted`, `ready` or `saved`. On `pending`, call `readCandidates` again later for the same job and do nothing else. `navigation-pending` means a page load from an earlier call ran past its time limit and is still running; it will empty the bar, so call again after it finishes. `deadline-passed` means the time limit ran out before the final click or Enter; preparatory clicks may already have occurred. Any other status means stop and inspect the page; it is never a reason to resubmit, click again or upload again.

Clicking helpers first move the pointer to the target and compare the coordinates the page receives, then press that point through the tab's CDP capability. One measurement found a Playwright click on a job-page button took about 3 s and a checked press took 66 ms; these are observations, not performance guarantees. `input-misaligned` means clicks in this tab land off target: open a fresh tab and repeat the steps there (attachments stay in their own tab). Do not compensate with coordinates or AX clicks. `checkInput(tab)` runs the same check before a manual AX or coordinate click in a long-lived tab.

1. **Uploaded source:** `openLibrary(tab)` opens Add Images and lists its uploads. `listLibraryImages` and `sameAspectItems` narrow candidates for the same-source check in create.md. `attachLibraryImage(tab, libraryId, role)` selects the role column (`edit` = Attach to prompt, `style`, `image`) and succeeds only when that column shows the library ID.
2. **Generated candidate:** `attachJobImage(tab, jobId, index, role)` with `edit` or `style` presses the job page's Quick Edit or Use Style button, with no download or upload. It succeeds when the column shows `job:<jobId>/<index>` (`jobReferenceKey`). Image Prompt needs an upload. A page load drops every attachment, so when the bar already holds references the helper opens the job through its uncovered Create-feed link, and returns `navigation-would-clear` when no such link is visible. A full load also clears unsent prompt text. All helper full-load paths refuse with `navigation-would-clear` when a draft or references remain; preserve them or use a separate tab. When in doubt, attach generated candidates first.
3. `openCreate(tab)` returns to Create through the sidebar link and confirms that the role columns did not change; never `tab.goto` Create after attaching. `readReferences(tab)` reports every role column, and `clearReferences(tab)` empties them with the bar's own clear button.
4. `submitPrompt(tab, text, { references })` starts at the top of the Create feed, preserves an unrelated draft, refuses a mismatched read-back and sends Enter at most once. Pass the intended attachments, for example `{ edit: [jobReferenceKey(jobId, 2)], style: [libraryId] }`, or `{}` for none. Any other set, including a stale locked one, returns `references-mismatch` without submitting. The new job is identified by its position above the previous top row and by the full prompt text.
5. `readCandidates(tab, jobId)` waits for the decoded original. Compare candidates from one screenshot of that job, then `saveCandidate(tab, jobId, index, absoluteDir)` for the chosen index.

`timeoutMs` is a shared deadline for navigation waits, polling and scheduling clicks/Enter, not a strict wall-clock cap or cancellation guarantee. In-flight transport calls, DOM reads, media export and filesystem work may outlast it. A timed-out page load continues and blocks later actions until settled. Leave room below the `cua_repl` call timeout (30 s by default), or raise `timeout_ms`; do not launch concurrent helper calls on the same tab. PNG export, new uploads, Editor work, video and account actions keep their documented flows. The helpers were live-tested on 2026-09-29, including three authorized generations; see the evidence file.
