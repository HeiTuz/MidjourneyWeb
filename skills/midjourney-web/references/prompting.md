# Prepare prompts and correct mismatches

For a prompt-only request, return one copyable block unless alternatives were requested. Keep upload/reference-role instructions outside the block; local paths and unresolved placeholders are not usable website URLs. An explicitly chosen, available authoring workflow such as MPW owns prompt preparation; this skill owns authorized website execution. Do not claim a reference or parameter was applied until observed on the submitted job.

Describe subject, visible action, framing and treatment concretely. Put compatible parameters at the end with ASCII `--`; omit the Discord command prefix on web. Preserve exact supplied wording when execution rather than rewriting was requested. Read [Create](create.md) for version and attachment compatibility; do not invent current account settings when preparing text offline.

A still intended as a video start frame describes one visible moment. Camera travel and events unfolding over time belong in the motion prompt. Do not pack an entire sequence into one still.

Sources: [Prompt Basics](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics), [Parameter List](https://docs.midjourney.com/hc/en-us/articles/32859204029709-Parameter-List). Verify the relevant article before asserting model-specific ranges.

## Respond to feedback

Inspect actual output when available and change the smallest relevant factor. These are creative diagnostics, not guarantees:

| Mismatch | Next decision |
|---|---|
| Too photographic for a painted brief | Remove conflicting photographic treatment; specify brush texture, shape boundaries, shading and depth appropriate to the requested medium. Inspect active style/profile influences before proposing a change. |
| Identity or product design drifts | Verify original source, role and model before adding descriptive text. Use an edit/reference workflow and inspect protected details. |
| Composition misses but style works | Change framing or subject placement while keeping the chosen style inputs. A viewpoint change uses [camera-edits.md](camera-edits.md). |
| One object or region is wrong | Use targeted editing of the chosen original and compare protected areas afterward. |
| The whole direction misses | Revisit the brief and references before generating more variations of the same mismatch. |

“More painted” changes the current task, not every future request. Separate must-have constraints from optional polish. Stop when the requested constraints are met or the authorized iteration scope is exhausted; do not label the least-bad candidate compliant. Report the remaining visual failure plainly.
